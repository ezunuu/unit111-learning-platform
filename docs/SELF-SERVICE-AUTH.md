# Өөрөө бүртгүүлэх, нууц үг сэргээх

Бүртгүүлэхэд нэр, и-мэйл, 12-оос доошгүй тэмдэгттэй нууц үг гэсэн 3 талбар бөглөнө. И-мэйлээр нэвтэрнэ; нэмэлт username сонгохгүй. Шинэ бүртгэл employee буюу суралцагчийн эрхтэй. И-мэйлийн том/жижиг үсэг, эхлэл/төгсгөлийн зайг нэгтгэн давхардлыг шалгана.

Нэвтрэх хуудасны “Нууц үгээ мартсан уу?” холбоосоор и-мэйлээ оруулна. 30 минут хүчинтэй нэг удаагийн холбоос явуулна. Токены hash л өгөгдлийн санд хадгалагдана. Шинэ нууц үг хадгалахад өмнөх session-үүд auth_version-оор хүчингүй болно. Бүртгэл болон reset үйлдэл CSRF, IP давтамжийн хязгаартай.

## И-мэйл холбоход

Одоогоор үйлчилгээ холбоогүй тул сэргээх и-мэйл илгээхгүй. Форм үүнийг тодорхой мэдээлнэ. Backend `.env` эсвэл hosting-ийн нууц тохиргоонд:

```dotenv
RESEND_API_KEY=таны-нууц-түлхүүр
MAIL_FROM=Сургалтын платформ <noreply@your-domain.example>
PASSWORD_RESET_ORIGIN=https://your-domain.example
```

RESEND_API_KEY-г код, Git эсвэл чатад оруулахгүй. MAIL_FROM-д өөрийн баталгаажуулсан илгээгч хаяг, PASSWORD_RESET_ORIGIN-д вебийн бодит хаягийг оруулна. API-г дахин эхлүүлнэ. Үйлчилгээ: [Resend и-мэйл илгээх API](https://resend.com/docs/api-reference/emails/send-email).

## Шинэчлэлт, шалгалт

API ба web-ийг хамт шинэчилж, `0021_brown_strong_guy.sql` migration-ийг ердийн runner-аар ажиллуулна. Локал unit111_admin_test дээр backup баталгаажуулсны дараа migration амжилттай ажилласан. Өмнөх password/role/сургалтын ахиц өөрчлөх migration байхгүй; users.auth_version анх 0 тул хуучин session-үүд ажиллана.

Бүртгэлийн payload-д role нэмэхийг хориглох, и-мэйлийн давхардал, CSRF, токены хугацаа, зэрэгцээ дахин ашиглалт, хуучин session хүчингүй болохыг шалгасан. И-мэйлийн илгээлтийг mock-оор тестэлсэн; бодит и-мэйл илгээгээгүй, бодит хэрэглэгчийн нууц үг өөрчлөөгүй.
